一、後台中的「金流」是什麼？

在「金流與結算／金流對帳」後台脈絡下，金流指的是交易過程中資金的收付、對帳核銷、退款處理與撥款結算機制，涵蓋買家付款、第三方支付或銀行處理、平台核對帳務，到最終撥款或退款的整條資金流轉。

功能分頁定位
  • 金流對帳：核對每筆付款狀態、排查掉單與執行人工退款補記。
  • 待撥款 / 提領撥款：處理符合條件款項的撥款或提領。
  • 財務報表：彙整帳務收支與結算明細。
  • 收款金鑰：管理串接金流商的 API 憑證與設定。
核心交易狀態
  • 待付款：尚未完成付款或結果待同步，排程會定時查詢；逾時未付則釋放保留。
  • 已付款：金流商已確認收款成功。
  • 失敗/逾時：如逾期未付款或已取消，不進入正常撥款。
  • 待人工退款 / 已退款：已收款需退還者，完成外部退款並補記後轉為已退款。

二、流程梳理：如何與外部金流商協作？

協作核心在於讓平台的訂單狀態與金流商的金流狀態在正常與異常情境下保持最終一致性，並建立明確的例外處理 SOP。

1. 交易生命週期對齊表

流程階段 平台動作 外部金流商動作 協作確認重點
建立交易 建立交易紀錄、產生金流交易編號、鎖定庫存／額度 接收請求，回傳付款頁或 Token 確認單號映射與重試防重複規則
支付與回調 等待付款結果（待付款） 買家付款後發送非同步 Webhook 通知 對齊付款逾時時間（TTL）與回調重試策略
主動查詢補單 排程定時呼叫金流商 Query API 查詢 回傳單筆交易最新狀態 確認排程輪詢頻率與 API Rate Limit
退款處理 發起自動退款 API 或人工至金流後台操作並補記 執行刷退／匯退並回傳結果 確認支援全額／部分退款及 API 退刷期限
日結對帳 下載對帳檔並與內部帳務核銷 產出每日結算／對帳報表 確認日結切帳時間（Cut-off Time）

2. 技術防呆與營運例外協作

  • 雙重確認機制：結合 Webhook 非同步通知與定時排程 Query API 主動查證，避免網路波動或回調漏接導致狀態卡住。
  • 冪等性與簽章驗證：所有回調與查詢更新需驗證簽章並做冪等檢查，防止重複通知造成重複入帳或重複出貨。
  • 掉單與人工退款 SOP：買家反映已付款但後台仍為待付款時，持金流交易編號至金流商後台查證；遇到待人工退款或退款中(自動)卡住時，先停止自動重試，於金流商後台或銀行完成實際退款後再回平台補記。

三、Data Flow（資料流）

關鍵資料鍵值包含 Order ID（訂單編號）、Payment Txn ID（金流交易編號）、Gateway Ref ID（金流商外部單號）、Amount 與交易狀態。

1. 付款與定時對帳主資料流

[買家 / 消費者]
      │
      ▼ (1) 發起結帳／選擇支付方式
[平台前台 / 訂單服務]
      │  建立交易紀錄（Status: 待付款）、產生金流交易編號、鎖定庫存/額度
      ▼ (2) 呼叫建立付款請求（帶入 Order ID, Txn ID, Amount, Sign/金鑰）
[外部金流商 / 銀行]
      │
      ├───(3a) 買家完成付款 ──► 發送非同步 Webhook 通知 ──► [平台 API / Webhook Receiver]
      │                                                               │ 驗簽 + 冪等檢查
      │                                                               ▼
      │                                                      更新金流狀態為「已付款」
      │                                                      觸發訂單成立／出貨／撥款排程
      │
      ├───(3b) Webhook 漏接/延遲 ──► [平台定時對帳排程 (Cron Job)]

1. 付款與定時對帳流程圖

flowchart TD
    Start([買家發起結帳]) --> CreateOrder[平台建立交易紀錄
狀態：待付款
鎖定庫存 / 額度]
    CreateOrder --> CallGateway[呼叫外部金流商建立付款請求
帶入訂單編號、金流交易編號、簽章]
    CallGateway --> GatewayPay{外部金流商處理付款}

    GatewayPay -->|付款成功
發送 Webhook| Webhook[平台接收非同步通知
驗簽 + 冪等性檢查]
    Webhook --> Paid[更新狀態：已付款]
    Paid --> Settlement[進入後續履約 / 待撥款流程]

    GatewayPay -->|買家取消 / 付款失敗| Failed[更新狀態：失敗/逾時
釋放保留庫存 / 額度]

    GatewayPay -->|未收到回調
維持「待付款」| CronJob[系統對帳排程
定時向金流商 Query API 查詢]
    CronJob --> QueryResult{查詢結果判定}
    QueryResult -->|金流端已收款| Paid
    QueryResult -->|逾時未付款| Failed
    QueryResult -->|尚未付款且未逾時| WaitOrCS{買家是否反映已付款？}

    WaitOrCS -->|否| CronJob
    WaitOrCS -->|是| ManualCheck[營運/客服持金流交易編號
至金流商後台查證]
    ManualCheck -->|查證確實已收款| Paid
    ManualCheck -->|查證未收款| BuyerBank([請買家聯繫發卡行])

flowchart TD
    Trigger([觸發退款條件：

    Backfill --> Refunded
    ConfirmExternal -->|否| ExternalRefund
